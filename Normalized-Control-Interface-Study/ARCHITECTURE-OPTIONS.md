# 架构方案比较

## 1. 候选边界

```text
GNC Control Law
   ↓  (a) 物理 τ [N·m] / T [N]
   ↓  (b) 归一化 ν
Control Allocation
   ↓  (c) 归一化 u 或物理 δ/Ω
Aircraft Effectiveness Model
   ↓  (d) B、U、trim、执行器范围
Components（舵机/电机动力学）
```

PX4 的选择：控制器输出 (b)，分配器内部完成 `ν→u`，Aircraft 参数以 `B_u` 提供；
`S` 在分配器中由 `B_u` 计算。

## 2. 方案

### A. 物理量接口（当前 DEV）

```text
Rate PID → τ [N·m] → PINV(B_tau) → δ [rad]
```

| 维度 | 评价 |
|---|---|
| 复杂度 | 最低；无 S、无 ν、无换算 |
| 物理可解释性 | 最高：τ、δ、B_tau、残差全为 SI |
| 控制器独立性 | 控制器只依赖 N·m 接口，不依赖机型参数 |
| 多机型 | `B_tau`/`B_force` 由机型提供；控制器按物理对象重调 |
| PX4 对齐 | 数学等价，但控制空间不同（无 ν） |
| 迁移成本 | 0（现状） |
| 风险 | 无新增；跨机型复用控制器时增益仍需重调 |

### B. 归一化接口（PX4 风格）

```text
Rate PID → ν → Allocation(S,B_u) → u → δ
```

| 维度 | 评价 |
|---|---|
| 复杂度 | 中：新增 S、U、ν、gains 换算、双单位日志 |
| 物理可解释性 | 中：需同时记录 ν、S、τ；否则数值不可解释 |
| 控制器独立性 | 降低：增益以 ν 表示，依赖机型 `S` 与执行器范围 |
| 多机型 | 每个机型需换 S 与增益；同一 ν 增益不能直接跨机型 |
| PX4 对齐 | 最高：可直接对照 PX4 参数与 `scale` |
| 迁移成本 | 中高：改 Rate 输出、Topic、WTR、测试、增益表 |
| 风险 | S 的物理意义易被误解；饱和/积分限幅需换算 |

### C. 物理输出 + 分配器内部归一化

```text
Rate PID → τ [N·m] → Allocation: ν=S·τ → u → δ
```

接口不暴露 ν，只把归一化当作 PINV 的数值实现细节。

| 维度 | 评价 |
|---|---|
| 复杂度 | 低中：外部仍 SI，内部多一次乘除 |
| 物理可解释性 | 高：外部 τ，内部 S 可记录 |
| 控制器独立性 | 高：控制器不依赖 S |
| 多机型 | S 由 Allocation/Aircraft 配置，控制器不变 |
| PX4 对齐 | 数学可对齐，但 PX4 控制器输出的是 ν；不能直接复用 PX4 增益 |
| 迁移成本 | 低：只改 Allocation 内部 |
| 风险 | 若无收益，纯属多余复杂度；S 需测试一致性 |

### D. 双接口（物理主 + 可选归一化适配器）

```text
                    ┌─ 物理 τ ──→ PINV(B_tau) ─→ δ
Rate PID ─→ τ ──────┤
                    └─ 适配器 ν=S·τ ─→ PINV(B_u) ─→ δ
```

物理接口是默认；归一化只在明确的 PX4/INDI/跨机型需求下启用，两者共享同一
`B_p`、`U`、`trim`、限幅与状态反馈。

| 维度 | 评价 |
|---|---|
| 复杂度 | 中：一个适配层 + 等价性测试 |
| 物理可解释性 | 高：默认路径全 SI，归一化路径显式记录 S |
| 控制器独立性 | 高：默认物理 |
| 多机型 | S 由机型 effectiveness 提供；适配器通用 |
| PX4 对齐 | 高：可用 ν 路径对照 PX4 |
| 迁移成本 | 低（默认不启用） |
| 风险 | 双路径若不分清会成为长期兼容负担；必须限定使用场景 |

### E. 归一化放到 Aircraft 之后

```text
Allocation → δ/Ω → Aircraft → 归一化
```

不可行：分配器需要归一化空间来求解，Aircraft 只应提供物理效能与执行器范围；
放在 Aircraft 之后无法参与 PINV，且会让动力学依赖控制尺度。

## 3. 边界职责

| 内容 | 应归属 | 理由 |
|---|---|---|
| Rate PID 控制律 | `GNC/Control/Rate` | 控制算法，保持 SI |
| 物理力矩 `τ` | Rate→Allocation Topic（N·m） | 科学可解释、可日志、可验证 |
| 归一化尺度 `S` / 参考力矩 `w_ref` | Aircraft effectiveness 配置或 Allocation 配置 | 由 `B_p`、`U`、执行器范围决定，不是控制律 |
| 物理效能 `B_p` | Aircraft | 机型几何/气动/配平 |
| 执行器范围 `U` | Aircraft 装配 + Components 设备参数 | 行程/转速范围 |
| 通用 PINV 算法 | `GNC/Control/Allocation` | 不含机型常数 |
| 归一化矩阵 `B_u=B_p U` | Allocation 由 Aircraft 输入构造 | 通用变换 |
| 电机推力 | 独立一维通道 | 不并入六舵 PINV |
| 物理/归一化日志 | Results/WTR | 两者并存，物理为主 |

## 4. 多机型比较

| 机型 | 控制轴 | 效能矩阵 | 执行器 | 配平 | 动态效能 |
|---|---|---|---|---|---|
| 多旋翼 | 3 力矩 + 3 力 | 电机力/力矩 | 4–8 电机 | 通常零 | 推力随转速，B 常数近似 |
| 固定翼 | 3 力矩 + 推力 | 舵面/电机 | 4–8 舵 + 电机 | 有 | 随空速强变化 |
| 涵道尾座 | 3 力矩 + 1 推力 | 舵面力矩 + 电机力 | 6 舵 + 1 电机 | 非零（反扭矩） | `B_tau∝Ve²` |
| 过驱动 | 6 维 wrench | 6×n | n>6 | 可能非零 | 各异 |

共同点：都可抽象为 **6 维物理虚拟控制（3 力矩 + 3 力）→ 执行器**；
不同点：`B`、`U`、`n`、`trim`、动态尺度。因此通用接口应是 **物理 6 维 wrench**，
`S` 是机型特定的可选换算，不能成为跨机型固定常数。

## 5. 最小通用方案

不建议建立“归一化框架/注册中心”。最小方案是：

1. 保持 `control/torque_setpoint` 为 N·m，`thrust` 为 N；
2. 在 Allocation 输入处增加可选 `virtual_control`（ν）与 `scale` 字段，
   仅在需要时启用；
3. `S`/`w_ref`、`B_p`、`U`、`trim` 由机型 effectiveness 结构提供；
4. 通用 PINV 只接受 `B_u`、`u_trim`、限幅；
5. 电机保持独立 `T`/`Ω`；
6. 物理与归一化结果都进入日志，物理为权威。

这满足多机型扩展，又不引入大型抽象。
